# Task Manager API (1 спринт)

Финальный проект 5 модуля. RESTful API для управления задачами пользователей.

## Технологический стек
- **Java 17**
- **Spring Boot 4.1.1** (Web, Data JPA, Validation, Security)
- **Безопасность:** JWT
- **База данных:** PostgreSQL,  Liquibase (миграции)

- **Тестирование:** JUnit 5, Mockito, Spring MockMvc, H2 Database (для изоляции интеграционных тестов)
-**Мониторинг:** Spring Boot Actuator, Micrometer, Prometheus
-**Инфраструктура:** Docker, Docker Compose, GitHub Actions (CI/CD)

## особенности архитектуры
1. **Безопасность и JWT:** Stateless аутентификация. Эндпоинты защищены ролями (`USER`, `ADMIN`).
2. **Soft Delete:** Пользователи не удаляются из БД физически, а помечаются флагом `deleted`. Реализована защита от удаления последнего активного администратора.
3. **Глобальная обработка ошибок:** `@RestControllerAdvice` перехватывает все исключения и возвращает унифицированные JSON-ответы с правильными HTTP-статусами (400, 401, 403, 409, 500).
4. **Мониторинг:** Интеграция с Actuator. Эндпоинты `health` и `prometheus` открыты для систем мониторинга, а чувствительные данные (`env`, `heapdump`) защищены ролью `ADMIN`.
5. **Изолированное тестирование:** Интеграционные тесты используют встроенную БД H2 и `@TestPropertySource`, что позволяет прогонять тесты в CI/CD без поднятия Docker-контейнеров с PostgreSQL.
6. **CI/CD:** Настроен GitHub Actions пайплайн, который при каждом `push` автоматически компилирует код, прогоняет все тесты и собирает Docker-образ.


## Как запустить

Для запуска требуется установленный **Docker** и **Java 17+** (для сборки).

1. Склонируйте репозиторий:
   ```bash
   git clone 
   cd taskManager
   ```
2. Соберите проект (создаст JAR-файл в папке target):
```
mvn clean package -DskipTests
```
3. Запустите приложение и базу данных командой
```bash
docker-compose up --build
```

При первом запуске Liquibase автоматически создаст таблицы, а DataInitializer заполнит базу тестовыми данными.

## Тестовые данные
При первом запуске в базе создаются:
Пользователь 1 (Admin): id = 1, username: Юрий
Пользователь 2 (User): id = 2, username: Анжелика Устинова и несколько тестовых задач, привязанных к этим пользователям.

## Тестирование
Проект покрыт Unit и Интеграционными тестами. Для запуска тестов локально (потребуется JDK 17+):
```bash
mvn clean test
```

## API Endpoints

> Для защищенных эндпоинтов необходимо сначала получить JWT-токен через `/api/auth/login` и передавать его в заголовке:  
> `Authorization: Bearer <ваш_токен>`

### Аутентификация (Публичные)

#### `POST /api/auth/register` — Регистрация нового пользователя
Доступно всем без токена. Роль жестко назначается как `USER`
```json
{
  "username": "newuser",
  "email": "newuser@example.com",
  "password": "password123"
}
```

#### `POST /api/auth/login` — Получение JWT токена
```json
{
  "username": "Юрий",
  "password": "admin123"
}
```

---

### Пользователи (Требуют JWT)

#### `GET /api/users` — Список всех пользователей
- **ADMIN:** видит всех активных пользователей.
- **USER:** доступ запрещен (403 Forbidden).

#### `GET /api/users/{id}` — Получить пользователя по ID
- **ADMIN:** может получить любого пользователя.
- **USER:** может получить только свой профиль (иначе 403).

#### `PUT /api/users/{id}` — Обновление пользователя
- **ADMIN:** может обновить любого пользователя, включая смену его роли (`role`).
- **USER:** может обновить только свой профиль (email, password, username), но **не может** изменить роль.

#### `DELETE /api/users/{id}` — Удаление пользователя (Soft Delete)
- **Доступ:** Только `ADMIN`.
- **Логика:** Пользователь помечается как `deleted = true`, физически из БД не стирается (сохраняется история задач).
- **Защита:** Нельзя удалить последнего активного администратора в системе.
- *Примечание:* Миграция добавления колонок `deleted` и `deleted_at` реализована через отдельный `changeSet` в Liquibase.

---

### Задачи (Требуют JWT)

#### `GET /api/tasks` — Получить список задач
- **ADMIN:** видит все задачи в системе.
- **USER:** видит только свои собственные задачи.

#### `GET /api/tasks?userId={id}` — Получить задачи конкретного пользователя
- **ADMIN:** может посмотреть задачи любого пользователя по его `id`.
- **USER:** может посмотреть только свои задачи. При попытке передать чужой `userId` вернется `403 Forbidden`.
